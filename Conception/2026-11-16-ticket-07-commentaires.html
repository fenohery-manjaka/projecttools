Fichier : phpunit.xml

Tu as remplacé la base des tests par une base MySQL projecttools_testing. Elle n'existe que sur ton poste : ni sur GitHub, ni chez les autres. Tout le monde verrait ses tests échouer. Remets les deux lignes d'origine :

4L'alias de type : corriger la documentation, pas encore de code

Fichier : docs/architecture.md, section « Commentaires », étape 1

Ta documentation dit d'ajouter l'alias « dans le morphMap du CoreServiceProvider ». Rien n'est déclaré dans le code, et il ne faut pas le faire ainsi :

Piège : Relation::enforceMorphMap() oblige à donner un alias à tous les modèles, y compris User. Or la table des rôles (model_has_roles) contient déjà App\Models\User dans model_type : avec un alias user, plus personne n'aurait ses rôles. Et le noyau ne doit pas connaître les modules (Tâches, Idées…).

La bonne règle : chaque module déclare l'alias de son modèle dans sa méthode boot(), avec morphMap (sans « enforce »). Les lignes déjà écrites avec un nom de classe continuent de fonctionner. Pour les tâches, ce sera au ticket 08 : 

// app/Modules/Tasks/TasksModule.php
public function boot(): void
{
    Relation::morphMap(['task' => Task::class]);
}

Corrige donc l'étape 1 de la section « Commentaires » en ce sens. Pour le ticket 07, ton Relation::morphMap() dans le test suffit.

Améliorations (bienvenues, pas bloquantes)

aLe journal répète le nom de l'auteur

Dans PostComment, tu écris "{$author->name} a ajouté un commentaire à …". Le journal enregistre déjà l'auteur à part (colonne user_id), et les autres messages commencent par le verbe : "a créé le projet « X »". Écris "a commenté « {$commentable->commentTitle()} »".

« 07 noyau-commentaire module » ne suit pas la convention du projet. Exemple : feat(core): ajouter les commentaires et les mentions. Pour tes prochains commits, utilise ce format.
