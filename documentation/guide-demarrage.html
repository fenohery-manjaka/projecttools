1

Installer les outils

À faire une seule fois sur votre ordinateur. Les instructions visent Windows ; sur Mac ou Linux, les mêmes outils s'installent avec le gestionnaire de paquets habituel.

Outil Version Où le trouver
PHP + Composer PHP 8.3 ou plus, Composer 2 Laragon (version « Full ») installe les deux.
Node.js + npm 22 (LTS) nodejs.org
Git 2.40 ou plus git-scm.com (installe aussi Git Bash et la connexion à GitHub)
Éditeur — VS Code ou PhpStorm, au choix

Vérifier l'installation

Ouvrez un terminal (Git Bash, PowerShell ou le terminal de Laragon) et lancez : 

php -v
composer --version
node -v
git --version
Vous devez voirPHP 8.3 (ou plus), Composer 2.x, Node v22.x et une version de Git. Si une commande est « introuvable », l'outil n'est pas installé ou pas dans le PATH : rouvrez le terminal après l'installation.

Extensions PHP nécessaires

php -m

La liste doit contenir pdo_sqlite, sqlite3, fileinfo et mbstring. Sinon, dans Laragon : menu PHP › Extensions, cochez-les, puis redémarrez Laragon.

2

Accéder au dépôt GitHub

Le code vit sur github.com/fenohery-manjaka/projecttools.

Accepter l'invitation

Vous avez reçu un e-mail de GitHub. Acceptez l'invitation, ou ouvrez la page des invitations du dépôt en étant connecté à votre compte GitHub.

Dire à Git qui vous êtes

Utilisez le même e-mail que sur votre compte GitHub, pour que vos commits vous soient attribués. 

git config --global user.name "Prénom Nom"
git config --global user.email "vous@exemple.com"

Se connecter à GitHub

Rien à faire à l'avance : la première fois que Git parle à GitHub (étape suivante), une fenêtre du navigateur s'ouvre pour vous connecter. Acceptez, et Git s'en souviendra.

3

Récupérer et lancer le projet

On télécharge le code, on installe tout ce dont il a besoin, on remplit une base de test, puis on démarre l'application sur votre ordinateur.

Télécharger le code

Placez-vous dans le dossier de vos projets (avec Laragon : C:\laragon\www), puis : 

git clone https://github.com/fenohery-manjaka/projecttools.git
cd projecttools

Tout installer

Une seule commande installe les dépendances PHP et JavaScript, crée le fichier de configuration .env, la base de données et construit l'interface. Comptez quelques minutes. 

composer setup

Si la commande demande de créer la base de données SQLite, répondez yes.

Remplir la base avec des données de test

php artisan db:seed

Démarrer l'application

composer dev

Laissez ce terminal ouvert : il fait tourner l'application et recharge l'interface à chaque modification. Ouvrez http://localhost:8000. Pour arrêter : Ctrl + C.

Compte de test Mot de passe Rôle
test@example.com password Super admin : voit et peut tout
contributeur@example.com password Contributeur : droits limités, utile pour tester un refus
Vous devez voirla page « Projets » avec deux projets, après connexion avec test@example.com.

Ces comptes n'existent que sur votre ordinateur. Pour repartir de zéro à tout moment : php artisan migrate:fresh --seed (efface la base locale et la recrée).

4

Comprendre avant de coder

Une demi-heure de lecture évite des heures de corrections. Tout est dans le dossier docs/ du projet.

À lire Pourquoi
docs/plan.md Ce qu'on construit, les décisions déjà prises, l'ordre des lots.
docs/architecture.md Les modules, les contrôles d'accès, comment créer un module.
docs/conventions.md Les règles de code, de branches, de commits et de tests.
app/Modules/Projects/ Le module modèle : quand vous créez quelque chose, copiez sa façon de faire.
docs/tickets/ Les tickets, rédigés avec le contexte, les fichiers autorisés et les critères d'acceptation.

Vous utilisez un assistant IA (Claude Code, Cursor, Copilot…) ? Lancez une fois php artisan boost:install : il reçoit les règles du projet (.ai/guidelines/projecttools.md) et les respecte.

5

Le chemin d'un ticket

Toujours le même chemin, du ticket à la fusion. L'exemple utilise le ticket 42 « sous-tâches » : remplacez le numéro et le nom par ceux de votre ticket.

a. Partir de la dernière version

git switch main
git pull

b. Créer votre branche

Un ticket = une branche. Nom : lot<numéro du lot>/<numéro du ticket>-<sujet court>. 

git switch -c lot1/42-sous-taches

c. Coder

Ne modifiez que les fichiers listés dans le ticket. Gardez composer dev ouvert et vérifiez dans le navigateur, avec le compte super admin et le compte contributeur.

d. Vérifier avant d'envoyer

composer ci:check

C'est exactement ce que GitHub vérifiera : mise en forme, types, analyse du code et tests. S'il signale un problème de mise en forme, ces deux commandes le corrigent toutes seules : 

composer lint
npm run check:fix
Vous devez voirtous les contrôles « passed » et tous les tests verts, avant de passer à la suite.

e. Enregistrer votre travail (commit)

Regardez d'abord ce qui a changé, puis ajoutez les fichiers du ticket : 

git status
git add app/Modules/Tasks resources/js/pages/tasks tests/Feature/Modules/Tasks
git commit -m "feat(tasks): ajouter les sous-tâches d'une tâche"

Le message tient en une phrase, en français, au format type(module): ce que fait le changement. Types courants : feat (nouvelle fonctionnalité), fix (correction), docs, style, test, refactor. Vous pouvez faire plusieurs commits sur la même branche.

f. Envoyer votre branche sur GitHub

git push -u origin lot1/42-sous-taches

g. Ouvrir la pull request

Git affiche un lien après l'envoi ; sinon, ouvrez le dépôt sur GitHub : un bandeau jaune propose « Compare & pull request ».

  • branche de base : main ;
  • titre : le message de votre commit ;
  • remplissez le modèle qui s'affiche (ce qui change, cases à cocher, capture d'écran) ;
  • si le ticket est sur GitHub, écrivez Closes #42 : il se fermera tout seul à la fusion.
Vous devez voirla vérification GitHub (« tests ») passer au vert en quelques minutes, puis la demande de relecture.

h. Après la relecture

On vous demande des corrections ? Corrigez sur la même branche, refaites composer ci:check, un commit, puis : 

git push

La pull request se met à jour toute seule. Ne la fusionnez jamais vous-même : c'est le relecteur qui le fait.

i. Une fois fusionnée

git switch main
git pull
git branch -d lot1/42-sous-taches

Vous êtes prêt pour le ticket suivant : retour à l'étape a.

6

Les règles à ne jamais enfreindre

  • Envoyer directement sur main. Tout passe par une branche et une pull request.
  • Committer le fichier .env, la base database/database.sqlite, vendor/ ou node_modules/. Ils sont ignorés exprès : ne les forcez pas.
  • Écrire un mot de passe, une clé ou un jeton dans le code. Le dépôt est public : tout ce qui est envoyé est visible par tous, même après suppression.
  • Modifier un fichier qui n'est pas listé dans le ticket, en particulier app/Modules/Core, config/, bootstrap/ et routes/. Si c'est nécessaire, demandez d'abord.
  • Utiliser git push --force, ou fusionner votre propre pull request.
  • Ajouter une bibliothèque (Composer ou npm) sans accord.
7

Quand ça coince

composer setup s'arrête sur une erreur d'extension PHP

Il manque une extension (souvent pdo_sqlite, sqlite3 ou fileinfo). Activez-la dans Laragon (PHP › Extensions), redémarrez Laragon, rouvrez le terminal et relancez composer setup.

Page d'erreur « Vite manifest » ou page blanche

L'interface n'est pas construite ou composer dev n'est pas lancé. Lancez composer dev, ou une fois npm run build.

« Address already in use » ou le port 8000 est occupé

Une autre application utilise le port 8000 (souvent un autre projet lancé). Arrêtez-la avec Ctrl + C dans son terminal, puis relancez composer dev.

La vérification GitHub de ma pull request est rouge

Cliquez sur « Details » à côté de la vérification pour lire l'erreur. Relancez composer ci:check chez vous : vous verrez la même erreur. Corrigez, commit, git push.

GitHub signale un conflit sur ma pull request

Quelqu'un a modifié les mêmes lignes entre-temps. Récupérez la dernière version dans votre branche : 

git switch main
git pull
git switch lot1/42-sous-taches
git merge main

Ouvrez les fichiers signalés, gardez la bonne version entre les marques <<<<<<< et >>>>>>>, supprimez les marques, puis git add, git commit et git push. En cas de doute, demandez avant.

« Permission denied » ou « Repository not found » au moment d'envoyer

L'invitation n'est pas acceptée, ou Git est connecté avec un autre compte. Vérifiez l'invitation (étape 2) ; sous Windows, supprimez l'identifiant « git:https://github.com » dans le Gestionnaire d'identification, puis renvoyez : la fenêtre de connexion réapparaît.

J'ai fait une erreur dans mon dernier commit, pas encore envoyé

Corrigez les fichiers, puis git add et un nouveau commit. Ne réécrivez pas l'historique d'une branche déjà envoyée.

Toujours bloqué ?Demandez de l'aide en collant la commande lancée et le message d'erreur complet (pas une capture coupée). Plus la question est précise, plus la réponse est rapide.

Ce guide vit dans le projet : documentation/guide-demarrage.html. Une étape fausse ou manquante ? Proposez la correction dans une pull request.
