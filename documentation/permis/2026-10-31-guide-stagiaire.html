Le problème

Rahaja, stagiaire, vient d'être ajouté comme collaborateur du dépôt GitHub. Il n'a jamais récupéré ni lancé le projet, et rien ne lui explique le chemin complet : installer les outils, lancer l'application, prendre un ticket, ouvrir une pull request. Les règles existent (docs/conventions.md) mais supposent qu'on sait déjà faire. Conséquence : il risque de bloquer dès l'installation, ou d'envoyer directement sur main, ou d'envoyer le fichier .env, et vous passez votre temps à dépanner au lieu de relire.

Ce que je propose

Un guide HTML pas à pas, lisible sans rien installer, et un premier petit ticket pour faire le chemin une fois avant le lot 1.

Aujourd'hui
docs/conventions.md
« Créer une branche depuis main… »
« composer ci:check… »
« Ouvrir une pull request… »

Des règles justes, mais rien sur l'installation, ni sur Git pas à pas, ni sur quoi faire quand ça coince.

Ticket d'essai : traduire en français les pages de connexion, d'inscription et de mot de passe, encore en anglais. Un vrai besoin, sans risque, facile à relire : Rahaja fait une fois tout le chemin jusqu'à la pull request.
Envoi : GitHub n'affiche pas un fichier HTML comme une page. La première fois, vous lui envoyez le fichier (e-mail, messagerie) ; ensuite il le retrouve dans le projet.

Le guide s'ouvre sans connexion internet et se lit sur téléphone, sans débordement.
Le ticket d'essai contient toutes les rubriques du modèle de ticket.
